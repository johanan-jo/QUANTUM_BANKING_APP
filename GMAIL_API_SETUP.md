# Gmail API OAuth 2.0 Integration & Deployment Guide

This guide walks you through configuring the **Google Gmail API using OAuth 2.0** for Quantum Banking. This replaces the expired SendGrid service and bypasses Render's outbound SMTP restrictions by using HTTPS API requests.

---

## 1. Google Cloud Console Configuration

### Step 1: Create or Select a Project
1. Go to [Google Cloud Console](https://console.cloud.google.com/).
2. Click the project dropdown at the top and click **New Project**.
3. Name it `Quantum-Banking-API` and click **Create**.

### Step 2: Enable the Gmail API
1. In the search bar at the top, search for **Gmail API**.
2. Click on **Gmail API** and click the **Enable** button.

### Step 3: Configure OAuth Consent Screen
1. In the left navigation menu, go to **APIs & Services** > **OAuth consent screen**.
2. Choose **External** for User Type and click **Create**.
3. Fill in the required fields:
   - **App name**: `Quantum Banking`
   - **User support email**: Select your Gmail address.
   - **Developer contact information**: Enter your email address.
4. Click **Save and Continue**.
5. **Scopes**:
   - Click **Add or Remove Scopes**.
   - Filter or manually add the scope: `https://www.googleapis.com/auth/gmail.send`
   - Click **Update** and then **Save and Continue**.
6. **Test Users**:
   - Click **+ Add Users**.
   - Enter your sender Gmail address (the one that will send OTP emails) and any email you want to test with.
   - Click **Save and Continue** and finish the wizard.

### Step 4: Create OAuth 2.0 Client Credentials
1. Go to **APIs & Services** > **Credentials**.
2. Click **+ Create Credentials** at the top and select **OAuth client ID**.
3. Set **Application type** to **Desktop app**.
4. Name it `Quantum Banking Desktop Auth`.
5. Click **Create**.
6. You will see a dialog with:
   - **Client ID** (e.g. `123456789-xxxxxx.apps.googleusercontent.com`)
   - **Client Secret** (e.g. `GOCSPX-xxxxxxxxxxxxxx`)
7. Click **Download JSON** (save it as `client_secret.json`) or copy the Client ID and Client Secret.

## 2. Obtain Your Refresh Token Locally

We have provided a dedicated helper script: [`backend/scripts/get_refresh_token.py`](file:///c:/Users/johan/Downloads/LIL3/LIL3/backend/scripts/get_refresh_token.py).

### Option A: Using `client_secret.json`
1. Place your downloaded `client_secret.json` file inside the `backend/` or `backend/scripts/` folder.
2. Run:
   ```bash
   cd backend
   python scripts/get_refresh_token.py
   ```

### Option B: Interactive Prompt
1. Run:
   ```bash
   cd backend
   python scripts/get_refresh_token.py
   ```
2. When prompted, paste your **Client ID** and **Client Secret**.

### Completing the Consent Flow
1. Your default web browser will automatically open with Google's OAuth consent screen.
2. Choose your Gmail account (the authorized sender).
3. If you see a *"Google hasn't verified this app"* warning, click **Advanced** -> **Go to Quantum Banking (unsafe)**.
4. Grant permission to **Send email on your behalf**.
5. Return to your terminal. The script will output:
   ```env
   GMAIL_CLIENT_ID=your-client-id.apps.googleusercontent.com
   GMAIL_CLIENT_SECRET=GOCSPX-your-client-secret
   GMAIL_REFRESH_TOKEN=1//04xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```

## 3. Environment Variables Reference

Add these variables to your local `backend/.env` file and your **Render Dashboard**:

| Variable | Description | Example |
| :--- | :--- | :--- |
| `GMAIL_CLIENT_ID` | OAuth 2.0 Client ID from Google Cloud Console | `123456789.apps.googleusercontent.com` |
| `GMAIL_CLIENT_SECRET` | OAuth 2.0 Client Secret from Google Cloud Console | `GOCSPX-yourSecretKey` |
| `GMAIL_REFRESH_TOKEN` | Refresh token generated by `get_refresh_token.py` | `1//04abc123...` |
| `GMAIL_SENDER_EMAIL` | The Gmail address that granted OAuth access | `quantumbankapp@gmail.com` |

## 5. Deployment Instructions for Render

Render blocks outbound SMTP traffic on ports 25, 465, and 587. Because the Gmail API operates entirely over standard HTTPS port 443 (`https://gmail.googleapis.com`), it works reliably on Render.

1. Log into your [Render Dashboard](https://dashboard.render.com/).
2. Select your `quantum-banking-backend` service.
3. Navigate to **Environment**.
4. Add the following environment variables:
   - `GMAIL_CLIENT_ID`: *(Value from Google Cloud Console)*
   - `GMAIL_CLIENT_SECRET`: *(Value from Google Cloud Console)*
   - `GMAIL_REFRESH_TOKEN`: *(Value from `get_refresh_token.py`)*
   - `GMAIL_SENDER_EMAIL`: *(Your Gmail address)*
   - `DEBUG_OTP`: `false`
5. Remove any obsolete SendGrid variables (`SENDGRID_API_KEY`).
6. Click **Save Changes**. Render will automatically trigger a redeploy.
7. Monitor the deployment logs to confirm that requirements install successfully and Gunicorn starts.

## 6. Troubleshooting Common Issues

### Issue 1: "Token has been expired or revoked" (`RefreshError`)
- **Cause**: If your Google Cloud OAuth Consent Screen is in **"Testing"** mode, Google automatically expires OAuth refresh tokens after **7 days**.
- **Fix**: In Google Cloud Console > **OAuth consent screen**, click **Publish App** to switch from "Testing" to "In Production". (Verification by Google is NOT required for private apps with personal usage).

### Issue 2: "Precondition check failed" or "403 Forbidden"
- **Cause**: The `GMAIL_SENDER_EMAIL` does not match the Google account that authorized the refresh token.
- **Fix**: Make sure `GMAIL_SENDER_EMAIL` is set to the exact email address you logged into when running `get_refresh_token.py`.

### Issue 3: "Access blocked: This app's request is invalid"
- **Cause**: The OAuth client was created as a Web application without redirect URIs.
- **Fix**: When creating the OAuth Client ID in Google Cloud Console, select **Desktop app** (Installed application).
